# Data file reference

[← Contents](README.md)

Everything ClassKernel stores is in one data folder of plain UTF-8 `.csv` and `.md` files. This page lists every file
and its columns, for anyone who wants to read, check or repair the data outside the app. For the everyday view, see
[Your data and backups](user-guide/11-your-data.md).

**Conventions**

- The first row of every `.csv` is its column names.
- **Dates** (`date`) are `YYYY-MM-DD` in the app's time zone.
- **Timestamps** (`timestamp`, `start`, `end`, `updated`) are ISO 8601 in UTC, e.g. `2026-10-08T07:45:12.345Z`.
- **Numbers** are saved with a decimal point (`61.5`), so the files stay machine-readable, even though the app
  shows a decimal comma (`61,5`).
- **Ids** (`id`, `student_id`, `desk_id`, `assessment_id`, `session_id`) are generated by the app; rows in other
  files refer to them. Don't change them by hand.
- Writes are atomic: each file is written in full to a temporary file, then renamed over the original.
- Close the app before editing files by hand, so it doesn't save over your changes.

## Folder layout

```
<data folder>/
  behaviours.csv              behaviour buttons (shared by all classes)
  topics.csv                  topic bank by grade
  cognitive_levels.csv        cognitive levels for tagging questions
  settings.csv                app-wide preferences
  timer_presets.csv           saved test-timer presets
  classes/<class name>/       one folder per class (see below)
  layouts/<template name>/    room templates: desks.csv + room.csv
  exports/                    spreadsheets saved with "Save to data folder"
  backups/<YYYY-MM-DD_hhmmss>/  automatic snapshots (today's, plus the last of each of 14 earlier days)
```

## App-wide files

### `behaviours.csv`

| Column | Meaning |
| --- | --- |
| `code` | Short code, unique, e.g. `HW-`. Behaviour events refer to it. |
| `label` | Text on the button. |
| `kind` | `positive` or `negative`. |
| `points` | Points recorded, e.g. `2`, `-1`. |
| `color` | Button colour, `#rrggbb`. |

The row order is the button order. `Q+` (*Asked and answered*) and `Q-` (*Unable to answer*) are the codes Pick a
student records; the dashboards count them as questions, not behaviour.

### `topics.csv`

| Column | Meaning |
| --- | --- |
| `grade` | Grade, matching a class's grade, e.g. `10`. |
| `area` | Content area, e.g. `Physics`. |
| `subtopic` | Topic a question can be tagged with. Empty on an area's placeholder row. |
| `short` | Short label for the marking-grid heading. |

A grade that shares another grade's list has no rows of its own; see `topic_links` in `settings.csv`.

### `cognitive_levels.csv`

| Column | Meaning |
| --- | --- |
| `code` | e.g. `L1`. |
| `label` | e.g. `Recall`. |

### `settings.csv`

Two columns, `key` and `value`:

| Key | Values |
| --- | --- |
| `privacy_mode` | `true` / `false` (missing means `true`) |
| `seat_name_style` | `full`, `firstInitial` or `first` |
| `seat_points` | Show running points on seats: `true` / `false` |
| `popover_flags`, `popover_notes` | Show flags / notes in the seat pop-up: `true` / `false` |
| `ui_scale` | Display size: `1`, `1.25`, `1.5` or `1.75` |
| `teaching_style` | `room` or `strip` (side panel) |
| `dock_side` | Side-panel edge: `left` or `right` |
| `lesson_bar_side` | Room-plan button edge: `top`, `right`, `bottom` or `left` |
| `reseat_pin` | SHA-256 hash of the reseat PIN (empty = no PIN) |
| `time_zone` | IANA zone, e.g. `Africa/Johannesburg` (empty = the computer's) |
| `mark_entry_enter` | `across` or `down` |
| `grade_scale` | `level` or `symbol` |
| `exam_weights` | The examinations' share (%) of the weighted mark per grade, `;`-separated, e.g. `10=60;12=75`. A grade not listed is 50. |
| `topic_links` | Grades that use another grade's topic list, `;`-separated, e.g. `11=10;12=10` (G11 and G12 use G10's list in `topics.csv`). |
| `report_school`, `report_teacher` | Parent-report header |
| `plugins_enabled` | Switched-on tools, `;`-separated ids: `class-dashboards`, `parent-reports`, `test-timer`, `clock`, `stopwatch`, `graph-paper`, `practical-graph`, `motion-graph`, `noise-meter` |

### `timer_presets.csv`

| Column | Meaning |
| --- | --- |
| `name` | Preset name. |
| `reading_minutes`, `writing_minutes` | Phase lengths. |
| `display` | `circle`, `hourglass` or `flip`. |
| `chime` | `true` / `false`. |

## Class files: `classes/<class name>/`

The folder name is the class name.

### `class.md`

Front matter, then the class notes in Markdown:

```
---
name: 10A Physical Sciences
year: 10
subject: Physical Sciences
room: Lab 3
archived: false
color: #1e7b46
---
# Notes
…
```

`year` is the class's **Grade**.

### `desks.csv`

The room layout, one row per item.

| Column | Meaning |
| --- | --- |
| `desk_id` | |
| `label` | Desk label or label-box text. |
| `shape` | `single`, `double`, `group4`, `group6`, `teacher`, `door`, `window` or `label`. |

| Column | Meaning |
| --- | --- |

### `lessons.csv`

One row per student per ended lesson; the seating insights are worked out from it.

| Column | Meaning |
| --- | --- |
| `session_id`, `date`, `timestamp` | The lesson. |
| `student_id`, `desk_id`, `desk_label` | Where the student sat. |
| `seatmates` | `;`-separated ids of the others at the desk. |
| `points`, `positives`, `negatives` | The student's behaviour that lesson. |

### `assessments.csv`

| Column | Meaning |
| --- | --- |
| `assessment_id`, `title`, `date` | |
| `total_marks` | Out of (for per-question tests, the sum of the questions). |
| `category` | e.g. `Test`, `Exam`. |
| `question_count` | `1` for a single mark. |
| `content_area` | e.g. `Physics`, or empty for mixed. |
| `kind` | `informal` or `exam` — which side of the weighted mark it counts towards. Missing in older files: `exam` when the category contains "exam", else `informal`. |
| `weight` | Its weight within its side: `1` normal, `2` counts double, `0` left out (missing = `1`). |

## Room templates: `layouts/<template name>/`

The same `desks.csv` and `room.csv` as a class, saved with **Save as template** in the room designer.

## Backups: `backups/<YYYY-MM-DD_hhmmss>/`

A full copy of the data folder (except `backups/` itself), taken each time the app starts. Every snapshot from today
is kept, plus the newest from each of the 14 most recent earlier days that have one; older ones are deleted. A restore
first takes a safety copy named `pre-restore-<stamp>`, which is never deleted automatically.
